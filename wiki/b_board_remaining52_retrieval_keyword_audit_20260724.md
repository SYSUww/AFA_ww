## 2. 当前检索词实际上如何产生

### 2.1 文档定位层：52题共享

`attempt_43` 使用以下内容机械构造文档定位 query：

```text
完整题干
+ 题型
+ 全部选项（选择题）
+ 通用领域同义词
+ 题面实体、法规名、报告名
+ 题面数值、年份和期限
```

随后对 `content_heavy` 文档 profile 做 BM25，先取 Top-60，再按 canonical 文档去重并继承组内最高分，最终保留 Top-20 候选；答案阶段再按 `alias_pruned` 策略选择最多10份文档。

因此 locator 的词不是模型生成的，主要来自题面、静态同义词词典和文档别名表。

### 2.2 模型选择题：26题

每个选项的基础 query 通常为：

```text
完整题干
+ 当前选项文本
```

证据门禁认为覆盖不足时，会基于题面动态生成选项断言、反证、标题、改写、单文档和邻居扩展查询；部分领域还会在模型前执行题目特定的 targeted literal 证据扫描或选项规则。

模型负责根据检索证据判断选项，不负责生成首轮检索词。

### 2.3 计算题：26题

计算题基础 query 为：

```text
完整题干
+ “计算题”
+ “数值 公式 单位 日期 条款 计算”
+ 题面触发的语义补充词
```

初次检索 Top-18，优先 `metric_row`、`formula_block`、`clause_block` 和 `article`。随后把题面本身作为证据，并按 8/16/24 条渐进式证据预算调用模型生成结构化计算计划。

若计划因缺输入或 grounding 失败，retry query 才会使用：

```text
模型上一轮 decision_summary
+ 本地校验器错误信息
```

因此计算题存在两类完全不同的检索词：

- 首轮：题面与静态语义规则生成；
- 重试：模型计划暴露的缺失变量与本地错误共同生成。

### 4.2 检索词来源可以分成五级

| 层级 | 来源 | 例子 | 合规与鲁棒性判断 |
|---|---|---|---|
| A | 题面动态抽取 | 公司、产品、法规、年份、数值、指标、期限 | 最安全，应作为主体 |
| B | 跨题通用领域词典 | `营业收入/营收`、`中期/半年度`、`不可撤销/连带责任` | 可用，但要版本化并离线评测 |
| C | 通用结构槽位 | `实体×年份×指标`、`条件—结果—例外`、`法规主体—行为—模态` | 最值得加强，能替代题目补丁 |
| D | 窄语义 overlay/固定短语 | 全年分红组件、特定法规复合短语 | 有迁移风险，只能抽象为跨题模板 |
| E | 模型摘要 + 校验错误 | 缺少某变量、期间/单位/grounding失败 | 只能在确认真缺证据后使用；当前会产生假补检索 |

此外，locator 的 `_hard_doc_aliases` 还包含固定公司、保险产品和法规别名。它不直接编码答案，但属于代码内语料映射；更合理的做法是迁移到可维护、来源明确的文档元数据/通用别名词典。

### 4.3 计算题补检索统计

26道计算题中，10道保存了 `calculation_retrieval_rounds`：

```text
fc_b_001(1)  fc_b_005(2)  fc_b_014(1)
fin_b_013(1) fin_b_015(2) fin_b_016(1) fin_b_017(1) fin_b_019(2)
ins_b_019(1) res_b_012(2)
```

这10题不能统一解释为“首轮缺证据”：

- **真覆盖不足**：如 `fc_b_005`、`fin_b_013/015/019`，首轮没有完整覆盖实体/期间/指标矩阵。
- **证据已在首轮但模型漏读或规划错**：如 `fc_b_001`、`fin_b_016/017`。
- **主体、年份或语义绑定错误**：如 `fc_b_014`、`fin_b_018`，扩大检索池反而可能加剧错绑。
- **单位/算术错误误路由为检索**：`res_b_012` 至少有一轮属于这种情况。

因此失败路由应先分成：

```text
结构/schema错误        -> 同证据重试
算术/单位/依赖错误     -> 本地纠错或同证据重试
主体/年份/期间错绑     -> 收紧证据范围后重试
明确缺少某个输入槽位   -> 只补该槽位
```

### 4.4 当前可归纳出的首轮通用模板

| 领域 | 首轮模板 |
|---|---|
| 金融合约 | `目标报告/发行人 + 条款/指标 + 主体 + 期间 + 条件/结果 + 数值/单位` |
| 财务报告 | `公司 × 年份/期间 × 原始指标 × 报表/附注口径`，每个必要格必须有证据 |
| 保险 | `产品 × 责任/免责/领取/退保条款 × 年龄/期间/状态 × max/min/差额/比例` |
| 监管 | `法规/制度 × 适用主体 × 行为/义务 × 条件 × 期限/阈值 × 模态/例外` |
| 行业研究 | `行业/主体 × 行为/指标 × 因果/比较关系`，先定位报告，再用首轮实体回填 |

## 5. 风险与后续评测

1. **不能把本审计接成 `QID -> 关键词`**。逐题表只用于离线回放和归纳通用查询模板。
2. **选择题历史 rescue 不完整**。A13 没保存逐选项的 `query_variants/rescue_queries`，所以“未记录补检索”不等于当时一定没有发生；后续产物应保存每阶段 query 与 evidence IDs。
3. **全文拼全部选项会产生确认偏差**。首轮应为每个原子命题同时生成支持、去结论宽查和反证/例外查询，不能只搜选项原句。
4. **合同、财报、保险和研究等通用选择题路径通常只搜索 `query_variants[0]`，浪费了已生成的其他变体**。监管路径会一次使用全部监管 query variants。前者应在受控预算内按证据覆盖缺口选择变体，而不是全加或全不用。
5. **监管仍有6题命中 targeted literal**：`reg_b_015/017/021/024/025/026`。其中 `reg_b_024` 的两法规组合尤其接近题目模板，应该抽象为“事实规则 + 评分/后果规则”的通用二跳检索。
6. **计算题的重试分类需要校准**。检索只应解决缺输入，不能用更多证据掩盖模型算术、单位和语义绑定错误。

下一步离线回放建议报告：

- 文档 Recall@1/3；
- 决定性 unit Recall@5/10 与 MRR；
- 必要槽位覆盖率；
- 主体/年份/期间/单位绑定错误数；
- 首轮已覆盖却仍发起补检索的“假重试率”；
- 去除固定 alias/targeted literal 后的召回变化；
- 单次联合选择题与逐选项调用的准确率、证据闭环率和 token 对比。
